Use this guide to observe Cursor CLI (`cursor-agent`) sessions. Cursor sends its
model requests through Cursor's own backend, which Relay cannot proxy, so Cursor is
observed through its hooks only.

**What the CLI reports today (Cursor CLI 2026.10.01, verified in a live headless
run).** The CLI fires `sessionStart`, `preToolUse`, `postToolUse`,
`beforeShellExecution`, `afterShellExecution` and `sessionEnd`. Relay records the
session and every tool call with its input and output. The CLI does **not** fire
`beforeSubmitPrompt`, `afterAgentResponse` or `stop`, although its bundle defines
them, so prompts, responses and token counts are not recorded. Cursor keeps the
conversation's text (prompts and responses, without tools, tokens or timestamps) in
`~/.cursor/projects/<workspace>/agent-transcripts/<conversation_id>/`.

Where Cursor does fire them, Relay maps:

- `beforeSubmitPrompt` to a turn opened with the user's prompt, and `stop` to its
  close;
- `afterAgentResponse` to an LLM span per model step, with the response text, the
  model, and input, output and cache token counts;
- `preToolUse`, `postToolUse` and `postToolUseFailure` to tool spans; the shell, MCP
  and file hooks report the same executions and stay marks.

`afterAgentThought` is not installed: with any command registered for it, Cursor CLI
2026.10.01 loses its connection to Cursor's backend mid-session and the run fails.
Relay never blocks Cursor: every hook is allowed.

## Install

```bash
nemo-relay install cursor
```

This adds one entry per observed event to `~/.cursor/hooks.json`, running
`nemo-relay hook-forward cursor --forward-only --fail-open`, and registers a
`nemo-relay` MCP server in `~/.cursor/mcp.json`. Installed hooks forward only to the
authenticated shared gateway that `nemo-relay mcp` starts; Cursor starts that server
with each session, as Claude Code and Codex do with their Relay plugins. A headless
`cursor-agent -p` run needs `--approve-mcps`, or the server approved once. Every other
hook entry and MCP server is kept, an MCP server of the same name that Relay did not
write is refused, and `nemo-relay uninstall cursor` removes exactly what was added.

There is no `nemo-relay cursor` launcher: Cursor reads hooks only from its
`hooks.json`, so a per-run gateway has nothing to hand it.

## Limitations

- Verified against Cursor CLI 2026.10.x. `cursor-agent --version` prints a dated
  build; its commit suffix is ignored.
- Cursor also loads Claude Code's hook settings. A machine with Relay's Claude Code
  hooks installed can report a Cursor session through both routes.
- Managed daemon bundles do not include Cursor.
